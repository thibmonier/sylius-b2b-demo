## Règles du sprint 33

1. **Tests** seulement via `WORKER_ID=<worker> TEST_DB_NAME=b2b_<worker> TEST_CACHE_DIR=var/cache-<worker> bin/run-tests <arguments PHPUnit>`. Jamais `phpunit` en direct.
2. **Disque** : **aucun test ni rendu local sous 5 Go libres** (registre du 2026-10-28 : 5 Go au lancement) ; **aucune suite complète sous 6 Go** ; `bin/check-disk` avant chaque lot ; mémoire libre et swap relevés. Sous le seuil, le worker écrit tests et code mais ne lance rien, le dit dans son rapport et prépare la tâche suivante. Une seule suite complète à la fois.
3. **Un seul cache de rendu par worker** : `bin/render-page` réutilise le même cache, avec `bin/check-disk` avant chaque rendu ; aucun rendu sous le seuil ; aucun rendu en série sans nettoyage ni relevé de l'espace libre.
4. **Jamais de fichier `.env*`** (lecture, création, copie), dans la démo comme dans les dépôts de plugins.
5. **Aucun `rm` refusé contourné** ni aucun refus d'outil contourné par un autre chemin : le noter dans le rapport, avec la commande refusée, et continuer.
6. **Branche `feature/sprint-33-indexation-et-depots`** (arbre principal, déjà créée) pour la démo ; **pas de checkout dans l'arbre partagé**. Dans un dépôt de plugin : branche `chore/supply-chain-hardening` depuis la branche par défaut à jour (règle 29).
7. **Commits limités aux chemins nommés** : `git add <nouveaux fichiers>` puis `git commit -m "…" -- <chemins>` ; jamais `git commit -a` ni index partagé ; `git show --stat` avant chaque push. Commits Conventional Commits **avec le bon numéro de story** (US-207 ou US-209), relu contre la branche et la PR par `git log -1` avant le push.
8. **Pas de push, de tag, de release ni de PR sans la demande de l'orchestrateur** ; aucune commande Railway. **Seule exception, décidée au registre le 2026-10-28 (auteur : Thibaut)** : pour les dépôts de plugins d'US-209 seulement, push de la branche, ouverture de la PR et **fusion si la CI est verte** ; **jamais de tag ni de release** ; toute exception (CI rouge préexistante, dépôt sans CI, branche protégée qui exige une revue) est remontée à l'orchestrateur, qui la remonte à Thibaut, et la PR reste ouverte. Le dépôt de la démo reste soumis à la règle générale.
9. **Pas de maquette ce sprint.** Seule porte de Thibaut pour le code : le GO de la liste blanche et de l'activation de l'indexation (T-207-03), noté au [registre](./registre-decisions.md) avant d'activer l'indexation (le code et les tests peuvent s'écrire avant, activation désactivée par défaut).
10. **Aucun plugin modifié, sauf par US-209** (changements de CI et de `composer.json` `config` seulement, jamais de code ni de dépendance) ; `composer.lock` de la démo inchangé. **Refus par défaut** : toute route absente de la liste blanche répond `noindex, nofollow` ; le mode privé garde `noindex` et `Disallow: /` partout. Aucune valeur écrite en dur dans un gabarit ou une traduction : liste blanche, hôte canonique et dépôts viennent de la configuration versionnée.
11. **Aucun identifiant saisi en production** : les vérifications en production sont en lecture seule et sans connexion (`curl -sI`, `robots.txt`, `sitemap.xml`, pages vitrine publiques). **Aucune action chez un moteur de recherche** : la déclaration du sitemap est à Thibaut ; Claude ne touche à aucun compte (Search Console, GitHub hors dépôts de plugins).
12. **Ton neutre**, aucune comparaison avec Sylius Plus ni mention de l'offre de l'éditeur (politique de communication) ; **les plugins en recoupement et le plugin d'import ERP n'apparaissent ni dans les données structurées ni dans les descriptions** ; **aucun détail de sécurité dans les dépôts publics** (démo et plugins) : relevés, descriptions de PR et messages de commit ne citent ni secret, ni seuil, ni route d'administration, ni constat détaillé ; aucune marque réelle hors liste noire d'US-195.
13. **Test rouge commité seul**, cité dans la PR ; `bin/proof-rebase` (ou, à défaut, rebase puis `php bin/proof-refresh` et `php bin/proof-check`) si la PR ajoute ou supprime un fichier de tests ; PR de la démo fusionnées en série.
14. **Contrôle complet avant de rendre la main** : PHPStan sur tout le dépôt (`php -d memory_limit=2G vendor/bin/phpstan analyse`, `src` et `tests`), ECS (`src tests`), Rector, lint Twig et YAML ; aucun compteur écrit en dur.
15. **Mesures de production consignées le jour du déploiement** dans le fichier de tâches pour ce qui est public (US-207 : `robots.txt`, en-têtes d'une page listée et d'une page non listée, `sitemap.xml`, pa11y WCAG2AAA FR et EN, 320, 375 et 1280 px).
16. **« Que devient cet état après un déploiement ? »** : tout fichier, répertoire, cache ou variable d'environnement hors base est décrit (conteneur ou volume, ce qui le recrée au démarrage) et vérifié dans un conteneur neuf avant le merge. Le conteneur est neuf à chaque déploiement, la base survit. Ce sprint : le réglage d'activation de l'indexation est déclaré dans l'infrastructure (`preserve()` de toute variable posée à la main, sinon `config apply` la supprime) ; le sitemap est servi par l'application, pas écrit dans un fichier.
17. Les autres règles du gabarit (nettoyage de ses propres ressources, attente bornée, lecture sans filtrage, pas de `git` dans un worktree isolé, secrets fictifs) restent applicables.
18. **Aucune commande récursive ou destructive sur un chemin non vérifié** (incident du 2026-10-25 : `cp -Rn "$D"/. …` avec `$D` vide avait copié la racine du Mac). Jamais de `cp -R`, `rm -rf` ni `mv` sur un chemin issu d'une variable ou d'un glob sans :
    ```sh
    set -u
    D="…"
    [ -n "$D" ] && [ -d "$D" ] || { echo "chemin vide ou absent" >&2; exit 1; }
    case "$D" in "$PWD"/*) ;; *) echo "hors du dossier attendu" >&2; exit 1 ;; esac
    ```
    Le chemin est aussi vérifié sous le dossier attendu ; un glob sans résultat est traité comme vide. **Le script d'US-209 applique cette garde lui-même** : il refuse tout dépôt dont le chemin n'est pas sous `/Users/tmonier/Projects/sylius_plugins/` ou n'est pas un dépôt Git. L'orchestrateur n'approuve aucune commande sans cette garde. Les commandes de nettoyage destinées à Thibaut sont en **chemins absolus**, précédées d'un `du -sh`.
19. **Rejouer la séquence exacte de la CI avant de rendre la main** : la préparation de la CI (installation, fixtures, base) est rejouée telle quelle en local avant le push, quand le disque le permet ; la dernière ligne de sortie est citée. Pour un plugin d'US-209, la CI du dépôt est celle qui juge : la PR n'est fusionnée qu'au vert, run terminé.
20. **Aucune fusion avec une question ouverte** : avant tout enchaînement automatique de fusion, vérifier qu'aucune question à Thibaut n'est en suspens sur la PR (commentaire ou description) ; sinon la PR reste ouverte. **Toute décision ou tout GO est noté au registre avec son auteur** ; une phrase « accepté par Thibaut » n'est écrite que si elle y figure.
21. **Fichiers communs déclarés et attribués** (incident du sprint 29 : un commit avait embarqué les lignes d'un autre worker) : un fichier commun n'est commité qu'après `git diff -- <fichier>` relu ; il ne contient que ses lignes, sinon le worker attend et prévient l'orchestrateur. Matrice : [tasks/README.md](./tasks/README.md).
22. **Aucun test depuis un worktree dont `vendor` est un lien symbolique** : l'autoload de Composer résout le lien et exécute le code de l'arbre principal. Les tests se lancent dans l'arbre partagé.
23. **Captures réelles, relues à 1280 px avant la PR** : captures par `bin/render-page` avec les vignettes `b2b_photo*` ; si le rendu local est impossible faute de disque, captures de production (pages publiques, sans connexion), relues et dites dans la PR ; l'orchestrateur relit à 1280 px la home connectée et chaque page touchée avant d'ouvrir la PR ; un bloc à nombre fixe d'éléments a un test qui les compte.
24. **Parallélisme réglé sur la machine** : avant de lancer les workers, l'orchestrateur relève `df -h /`, la mémoire libre et le swap ; **au-delà de 2 Go de swap ou sous 7 Go de disque, au plus deux workers lancent des tests en même temps**. Le seuil se mesure avec `df`, jamais avec le Finder. Un worker qui n'a pas la main sur les tests le dit dans son rapport et prépare la tâche suivante.
25. **Échanges avec l'orchestrateur** : chaque réponse de l'orchestrateur à un worker cite l'**identifiant de la décision** (commit du registre) ; le worker ignore sans relance une notification d'attente antérieure à cette réponse. **`vendor/` de l'arbre partagé** : aucun worker n'y lance `composer install`, `composer update` ni `composer require`.
26. **Registre avant toute PR hors sprint ; relecture avant d'attendre** : tout correctif hors sprint (PR séparée) a sa ligne au [registre](./registre-decisions.md) **avant** l'ouverture de la PR, avec la date, l'auteur et la tâche ; un worker qui s'apprête à écrire « j'attends » **relit d'abord le registre et ses messages reçus**, et ne signale son attente que si aucune réponse ne la lève.
27. **Rouge prouvé** (action 1 de la rétro du sprint 32, incident : les fournisseurs de données des tests rouges d'US-205 étaient faux et corrigés dans le commit du code, donc ces tests n'avaient pas été vus rouges ; ceux d'US-206 avaient été corrigés deux fois) : avant de commiter des tests rouges, le worker (a) **relit les fournisseurs de données** (`#[DataProvider]` : les valeurs attendues, les pages, les locales), (b) **exécute les tests** par `bin/run-tests` et (c) **cite dans le message du commit la ligne d'échec de chaque test** (assertion ou exception, pas seulement « FAIL »), en vérifiant que l'échec vient de la fonctionnalité absente et non d'une donnée de test fausse. **Aucune correction des données d'un test rouge dans le commit du code** : une erreur trouvée plus tard donne un commit de test séparé, noté dans la PR. Si le disque empêche l'exécution (règle 2), le worker le dit dans le message du commit et dans son rapport, et la story n'est **pas comptée « rouge prouvé »** (noté au task-board). Pour US-209, le script est testé sur des dépôts de fixtures créés dans un dossier temporaire, avec la même exigence.
28. **Table « invariants de test » au cadrage** (action 2 de la rétro du sprint 32, incident : un conflit entre une maquette et un test « non modifié » n'a été vu qu'à l'implémentation) : la tâche de cadrage de chaque story liste, dans le fichier de tâches, **chaque test existant que la story touche** (assertion, fournisseur de données, fixture, script du runbook), ce qu'il fige aujourd'hui, ce que la story change, le traitement (inchangé, adapté ou nouveau test) et, pour toute adaptation, la **ligne du registre qui la décide avant l'action**. L'orchestrateur confronte la table au périmètre avant le premier commit de code ; tout conflit est noté au registre avec ses options. DoD : 0 test existant modifié sans ligne de registre, 0 conflit découvert après le démarrage du code. La table d'US-207 est préremplie au planning dans [tasks/US-207-tasks.md](./tasks/US-207-tasks.md), à confirmer par T-207-01.
29. **Dépôts de plugins : « plugin-repo-branch-check » et périmètre** (mémoire du projet, incident des branches fusionnées périmées ; GO du registre du 2026-10-28) : **dans chaque dépôt, avant tout commit**, `git fetch origin`, puis contrôle de la branche courante (`git branch --show-current`) et de son retard sur la branche par défaut distante ; une branche déjà fusionnée ou en retard est abandonnée au profit d'une nouvelle branche `chore/supply-chain-hardening` créée depuis `origin/<branche par défaut>`. Le script d'US-209 fait ce contrôle et refuse de continuer sinon. Les PR ne changent que `.github/` (workflows, `dependabot.yml`) et la section `config` de `composer.json` (`allow-plugins`, `policy`) ; **aucun code, aucune dépendance, aucun `composer.lock`**, aucun tag ni release (une version n'est pas nécessaire : seules la CI et `config` changent, et `config.policy` ne protège que la CI du dépôt). Messages de commit et descriptions de PR neutres et brefs, sans constat détaillé ni détail sensible. **Une PR par dépôt**, fusionnée seulement CI verte et run terminé ; un dépôt à CI rouge préexistante, sans CI ou à branche protégée est signalé, pas forcé.

## Preuves attendues dans le rapport

Pour chacun de PHPStan (dépôt entier), ECS (`src tests`), lint Twig, lint YAML et la suite : la **commande exacte** et la **dernière ligne de sortie**, ou « non exécuté » avec la raison (disque sous le seuil de la règle 2, par exemple). Un « vert » sans preuve est refusé. Pour les tests rouges : la ligne d'échec de chaque test, ou « non exécuté, story non comptée rouge prouvé ». Pour US-209 : la liste des dépôts traités (nom, PR, état de la CI, fusionnée oui ou non) et le résultat de `bin/plugin-supply-chain check` par dépôt.
