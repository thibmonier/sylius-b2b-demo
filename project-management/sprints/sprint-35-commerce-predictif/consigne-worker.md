> **Règle 33 (action 3 de la rétro du sprint 34) : « nouveau paquet commence par le test d'installation ». Un nouveau dépôt de paquet Composer (plugin, thème, bibliothèque) commence par le test d'installation ou de rendu avant le contenu. Le squelette de CI est copié d'un plugin existant (ex : quick-order), adapté au type de paquet, et le premier commit contient un test qui installe le paquet dans un projet Sylius vierge (dépôt local en `path` puis en `vcs`) et vérifie qu'il ne casse rien. Ce test échoue d'abord (paquet vide), puis passe une fois la structure minimale en place.**

## Règles du sprint 35

1. **Tests** seulement via `WORKER_ID=<worker> TEST_DB_NAME=b2b_<worker> TEST_CACHE_DIR=var/cache-<worker> bin/run-tests <arguments PHPUnit>`. Jamais `phpunit` en direct. **Pour US-217, US-238 : tests dans le dépôt du plugin ou du thème, pas dans la démo.**
2. **Disque** : **aucun test ni rendu local sous 5 Go libres** (registre du 2026-10-28 : 5,6 Go au lancement) ; **aucune suite complète sous 6 Go** ; `bin/check-disk` avant chaque lot ; mémoire libre et swap relevés. Sous le seuil, le worker écrit tests et code mais ne lance rien, le dit dans son rapport et prépare la tâche suivante. Une seule suite complète à la fois.
3. **Un seul cache de rendu par worker** : `bin/render-page` réutilise le même cache, avec `bin/check-disk` avant chaque rendu ; aucun rendu sous le seuil ; aucun rendu en série sans nettoyage ni relevé de l'espace libre. **US-217, US-238 : aucun rendu (dépôts séparés).** **US-218, US-219 : rendus dans la démo** (page « Mon compte » avec alertes, page « Plugins » mise à jour).
4. **Jamais de fichier `.env*`** (lecture, création, copie), dans la démo comme dans les dépôts du plugin et du thème.
5. **Aucun `rm` refusé contourné** ni aucun refus d'outil contourné par un autre chemin : le noter dans le rapport, avec la commande refusée, et continuer.
6. **Branche `feature/sprint-35-commerce-predictif`** (arbre principal, déjà créée) pour la démo ; **pas de checkout dans l'arbre partagé**. Pour le dépôt du plugin prédictif (US-217) : branche `feature/predictive-mvp` créée par le worker après la création du dépôt par l'orchestrateur. Pour le dépôt du thème (US-238) : branche `feature/theme-render-test` créée par le worker.
7. **Commits limités aux chemins nommés** : `git add <nouveaux fichiers>` puis `git commit -m "…" -- <chemins>` ; jamais `git commit -a` ni index partagé ; `git show --stat` avant chaque push. Commits Conventional Commits **avec le bon numéro de story** (US-217, US-218, US-219 ou US-238), relu contre la branche et la PR par `git log -1` avant le push.
8. **Pas de push, de tag, de release ni de PR sans la demande de l'orchestrateur** ; aucune commande Railway. **Exception décidée au registre le 2026-10-28 (auteur : Thibaut, règle 30)** : pour le dépôt du plugin prédictif d'US-217 seulement, **l'orchestrateur crée le dépôt public durci** ; le worker pousse sa branche `feature/predictive-mvp`, ouvre la PR ; **l'orchestrateur fusionne CI verte** ; **jamais de tag ni de release** sans GO de Thibaut. Pour le dépôt du thème d'US-238 : orchestrateur fusionne CI verte ; aucun tag ni release. Le dépôt de la démo reste soumis à la règle générale.
9. **Pas de maquette ce sprint.** Porte de Thibaut : le GO du tag v0.1.0 du plugin prédictif (T-219-03) après fusion de la PR du plugin, noté au [registre](./registre-decisions.md).

16. **« Que devient cet état après un déploiement ? »** : tout fichier, répertoire, cache ou variable d'environnement hors base est décrit (conteneur ou volume, ce qui le recrée au démarrage) et vérifié dans un conteneur neuf avant le merge. Le conteneur est neuf à chaque déploiement, la base survit. Ce sprint : **aucune variable d'environnement nouvelle dans la démo** ; le dépôt du plugin prédictif est créé une fois, à son URL définitive.
17. Les autres règles du gabarit (nettoyage de ses propres ressources, attente bornée, lecture sans filtrage, pas de `git` dans un worktree isolé, secrets fictifs) restent applicables.
18. **Aucune commande récursive ou destructive sur un chemin non vérifié** (incident du 2026-10-25 : `cp -Rn "$D"/. …` avec `$D` vide avait copié la racine du Mac). Jamais de `cp -R`, `rm -rf` ni `mv` sur un chemin issu d'une variable ou d'un glob sans :
    ```sh
    set -u
    D="…"
    [ -n "$D" ] && [ -d "$D" ] || { echo "chemin vide ou absent" >&2; exit 1; }
    case "$D" in "$PWD"/*) ;; *) echo "hors du dossier attendu" >&2; exit 1 ;; esac
    ```
    Le chemin est aussi vérifié sous le dossier attendu ; un glob sans résultat est traité comme vide. L'orchestrateur n'approuve aucune commande sans cette garde. Les commandes de nettoyage destinées à Thibaut sont en **chemins absolus**, précédées d'un `du -sh`.
19. **Rejouer la séquence exacte de la CI avant de rendre la main** : la préparation de la CI (installation, fixtures, base) est rejouée telle quelle en local avant le push, quand le disque le permet ; la dernière ligne de sortie est citée. **Pour US-217 et US-238, la CI du dépôt du plugin ou du thème juge** : la PR n'est fusionnée qu'au vert, run terminé.
20. **Aucune fusion avec une question ouverte** : avant tout enchaînement automatique de fusion, vérifier qu'aucune question à Thibaut n'est en suspens sur la PR (commentaire ou description) ; sinon la PR reste ouverte. **Toute décision ou tout GO est noté au registre avec son auteur** ; une phrase « accepté par Thibaut » n'est écrite que si elle y figure.
21. **Fichiers communs déclarés et attribués** (incident du sprint 29 : un commit avait embarqué les lignes d'un autre worker) : un fichier commun n'est commité qu'après `git diff -- <fichier>` relu ; il ne contient que ses lignes, sinon le worker attend et prévient l'orchestrateur. Matrice : [tasks/README.md](./tasks/README.md).
22. **Aucun test depuis un worktree dont `vendor` est un lien symbolique** : l'autoload de Composer résout le lien et exécute le code de l'arbre principal. Les tests se lancent dans l'arbre partagé.
23. **Captures réelles, relues à 1280 px avant la PR** : captures par `bin/render-page` avec les vignettes `b2b_photo*` ; si le rendu local est impossible faute de disque, captures de production (pages publiques, sans connexion), relues et dites dans la PR ; l'orchestrateur relit à 1280 px la home connectée et chaque page touchée avant d'ouvrir la PR ; un bloc à nombre fixe d'éléments a un test qui les compte. **US-217, US-238 : aucune capture (dépôts séparés).** **US-218, US-219 : captures de la page « Mon compte » avec alertes et de la page « Plugins » mise à jour**.
24. **Parallélisme réglé sur la machine** : avant de lancer les workers, l'orchestrateur relève `df -h /`, la mémoire libre et le swap ; **au-delà de 2 Go de swap ou sous 7 Go de disque, au plus deux workers lancent des tests en même temps**. Le seuil se mesure avec `df`, jamais avec le Finder. Un worker qui n'a pas la main sur les tests le dit dans son rapport et prépare la tâche suivante.
25. **Échanges avec l'orchestrateur** : chaque réponse de l'orchestrateur à un worker cite l'**identifiant de la décision** (commit du registre) ; le worker ignore sans relance une notification d'attente antérieure à cette réponse. **`vendor/` de l'arbre partagé** : aucun worker n'y lance `composer install`, `composer update` ni `composer require` (sauf US-219 après le tag v0.1.0).
26. **Registre avant toute PR hors sprint ; relecture avant d'attendre** : tout correctif hors sprint (PR séparée) a sa ligne au [registre](./registre-decisions.md) **avant** l'ouverture de la PR, avec la date, l'auteur et la tâche ; un worker qui s'apprête à écrire « j'attends » **relit d'abord le registre et ses messages reçus**, et ne signale son attente que si aucune réponse ne la lève.

Si le disque empêche l'exécution (règle 2), le worker le dit dans le message du commit et dans son rapport, et la story n'est **pas comptée « rouge prouvé »** (noté au task-board). **US-217, US-218, US-238, US-219 : toutes concernées.**
