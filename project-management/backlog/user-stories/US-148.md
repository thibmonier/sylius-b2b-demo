# US-148 — Plugins : limiteurs de débit typés `RateLimiterFactoryInterface` (Symfony 8)

> Epic : [EPIC-07](../epics/EPIC-07.md) · Persona : Thibaut (mainteneur des plugins) ; intégrateur Symfony 8 qui installe un plugin · MoSCoW : **Must** · Points : **3** · Sprint : 17
> Dépendances : dépôts `sylius-punchout-cxml-plugin`, `sylius-quote-request-plugin`, `sylius-quick-order-plugin`, `sylius-b2b-mcp-plugin`, `sylius-command-palette-plugin` ; démo en Symfony 8.1 (PR #35)

## Story

En tant qu'intégrateur qui installe un plugin tmonier dans un projet Symfony 8, je veux que ses limiteurs de débit s'injectent par `RateLimiterFactoryInterface`, afin que le plugin fonctionne aussi en autowiring et sans dépendre d'un type que Symfony 8 ne câble plus automatiquement.

## Contexte

Constat du 2026-10-19, pendant le passage de la démo en Symfony 8.1. En Symfony 8, le seul type autowirable pour un limiteur de débit est `Symfony\Component\RateLimiter\RateLimiterFactoryInterface` ; l'alias vers la classe concrète `RateLimiterFactory` n'existe plus. La démo a été corrigée (4 fichiers). Cinq plugins typent encore la classe concrète :

| Plugin | Occurrences |
|---|---|
| punchout-cxml | 10 |
| quote-request | 8 |
| quick-order | 8 |
| b2b-mcp | 8 |
| command-palette | 5 |

Ils compilent dans la démo parce que leurs services sont câblés explicitement. Un intégrateur qui surcharge un service en autowiring tombe en revanche sur « Cannot autowire service ».

Règles :
- Typage par `RateLimiterFactoryInterface` dans les constructeurs, propriétés et types de retour. `new RateLimiterFactory(...)` reste possible dans les tests.
- Compatibilité conservée avec Symfony 7.4 : l'interface existe depuis 7.3, la matrice CI de chaque plugin le vérifie.
- Une release patch par plugin, CHANGELOG à jour, puis montée de version dans la démo.
- Avant de commiter, vérifier dans chaque dépôt la branche courante après un `git fetch` (des branches fusionnées traînent localement).

```gherkin
    Alors les tests passent sur 7.4 et sur 8.1

  Scénario: Service surchargé en autowiring (alternatif)
    Étant donné un intégrateur qui redéclare un service du plugin avec autowire: true

  Scénario: Type concret restant (erreur)
    Étant donné le code d'un des cinq plugins

    Étant donné les cinq releases publiées
    Quand la démo monte leurs versions
    Alors la CI de la démo passe et aucun limiteur n'est contourné (tests de limitation existants verts)
```
