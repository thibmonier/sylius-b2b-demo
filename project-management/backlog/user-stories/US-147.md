# US-147 — Démo en PHP 8.5 (image, CI et plateforme Composer)

> Epic : [EPIC-01](../epics/EPIC-01.md) · Persona : Thibaut (mainteneur de la démo vitrine) · MoSCoW : **Must** · Points : **3** · Sprint : cible sprint 18 (replanifiée le 2026-10-21, repositionnement « recherche d'emploi »)
> Dépendances : US de montée Symfony 8.1 livrée (PR #35, ADR-0014) ; image `dunglas/frankenphp:1-php8.5-bookworm`

## Story

En tant que Thibaut, je veux que la démo tourne en PHP 8.5, afin qu'elle reste sur les versions les plus récentes proposées et serve de vitrine crédible de mon expertise.

## Contexte

Demande de Thibaut du 2026-10-19 : « il faut qu'une démo reste au plus haut des versions proposées ». Après le passage à Symfony 8.1, la démo reste en PHP 8.4 à trois endroits :

- l'image : `docker/Dockerfile`, `ARG PHP_IMAGE=dunglas/frankenphp:1-php8.4-bookworm@sha256:…` ;
- la CI : `.github/workflows/ci.yaml`, `php-version: "8.4"` dans deux jobs ;
- Composer : `config.platform.php` vaut `8.4.15` et `require.php` vaut `^8.4`.

Constats du 2026-10-19 :
- les dépendances se résolvent avec `platform.php` à 8.5.0, sans avis de sécurité ;
- l'image FrankenPHP PHP 8.5 est publiée ;
- la suite PHPUnit complète passe déjà sur le PHP 8.5.11 du poste local.

Règles :
- L'image reste épinglée par digest (`bin/check-pinned-refs`).
- Les extensions PHP et `docker/php.ini` sont vérifiées dans la nouvelle image : intl, gd ou imagick, pdo_mysql, opcache, apcu.
- Les dépréciations PHP 8.5 levées par le code de la démo sont corrigées ; celles des dépendances sont listées sans être corrigées.
- L'ADR-0013 (mode worker) reste valable : le comportement de `symfony/runtime` est revérifié en 8.5.

## Critères d'acceptation

```gherkin
Fonctionnalité: La démo tourne en PHP 8.5

  Scénario: Image de production (nominal)
    Étant donné l'image construite depuis main
    Quand on lance « php -v » dans le conteneur
    Alors la version affichée est 8.5.x
    Et la démo répond sur /healthz après un redéploiement Railway

  Scénario: CI sur PHP 8.5 (alternatif)
    Étant donné une PR sur la démo
    Quand la CI s'exécute
    Alors les jobs « Quality and smoke tests » et « Dependency audit » utilisent PHP 8.5 et passent

  Scénario: Plateforme Composer (alternatif)
    Étant donné composer.json
    Quand on lance « composer validate » puis « composer install »
    Alors config.platform.php vaut 8.5.x et le lock correspond

  Scénario: Image non épinglée (erreur)
    Étant donné un Dockerfile qui référence l'image PHP 8.5 par tag seulement
    Quand bin/check-pinned-refs s'exécute
    Alors le contrôle échoue

  Scénario: Extension manquante (erreur)
    Étant donné la nouvelle image
    Quand une extension requise par Sylius manque
    Alors le smoke test de l'image échoue avant tout déploiement
```

## Definition of Done

- [ ] Dockerfile, CI et composer.json en PHP 8.5, image épinglée par digest
- [ ] PHPUnit, ECS et PHPStan verts ; smoke tests de l'image verts
- [ ] Aucune dépréciation PHP 8.5 levée par `src/`
- [ ] Rendu réel vérifié en local (vitrine, compte acheteur, admin) puis sur Railway après redéploiement par Thibaut
- [ ] ADR-0014 complété (versions de la démo) ; mémoire « dernières versions » mise à jour

**Total estimé : à décomposer** (≈ 5 h).
