## Story

En tant que mainteneur des plugins, je veux que le pas « Run Non-unit PHPUnit tests » de chaque CI s'exécute même quand le pas unitaire échoue, afin qu'un commit rouge montre ses deux suites et que le rouge d'une story non unitaire soit toujours prouvé en CI (règle 26).

## Contexte

- Changement d'une ligne par dépôt, celui de health #5 : `if: ${{ !cancelled() }}` sur le pas non unitaire de `.github/workflows/build.yaml`, avec un commentaire ; le job échoue toujours si l'une des suites échoue.
- Relevé du 2026-11-22 : **30 plugins** ont un pas non unitaire sans cette condition.
- Une PR `ci:` par dépôt (dépôts indépendants), fusionnées par Thibaut ; aucune version de plugin n'est nécessaire (CI seulement).

## Critères d'acceptation

```gherkin
Fonctionnalité: Suite non unitaire toujours exécutée

  Scénario: Un test unitaire échoue (nominal)
    Étant donné un plugin dont un test unitaire échoue sur une assertion
    Quand la CI s'exécute
    Alors le pas « Run Non-unit PHPUnit tests » s'exécute quand même
    Et le job se termine en échec

  Scénario: Les deux suites passent (alternatif)
    Étant donné un plugin dont toutes les suites passent
    Quand la CI s'exécute
    Alors le job se termine en succès, comme avant

  Scénario: Exécution annulée (alternatif)
    Étant donné une exécution annulée pendant le pas unitaire
    Quand l'annulation est prise en compte
    Alors le pas non unitaire ne démarre pas

  Scénario: Un test non unitaire échoue après un unitaire en échec (erreur)
    Étant donné un test unitaire et un test non unitaire en échec
    Quand la CI s'exécute
    Alors les deux échecs apparaissent dans le même run

  Scénario: Le workflow modifié est audité (erreur)
    Étant donné le workflow modifié d'un plugin
    Quand zizmor l'analyse
    Alors aucun nouveau constat n'apparaît
```
