## Story

En tant que Camille, qui arrive sur un dépôt GitHub d'un des 24 plugins, je veux y trouver un lien vers la démo en ligne et vers le profil de l'auteur, afin de relier le code que je lis à la personne et à ses 25 ans de delivery.

## Contexte

**Réécriture du 2026-10-21.** La version d'origine renvoyait vers un site et une page de contact pour « promouvoir mes missions ». Le site n'existe pas et les missions ne sont plus l'objectif. Le bloc standard des README (outil `bin/vitrine-readme`) est complété par deux liens : la démo (`sylius-b2b.thibaut-monier.fr`) et le profil LinkedIn. Libellé neutre, factuel : « Démo en ligne » et « Auteur : Thibaut Monier ». Aucune formule de disponibilité ni d'offre dans les README (le profil porte ce message). Même ton que la charte d'US-063 (aucune comparaison). Livraison comme US-067 : une PR par dépôt, un GO unique de merge par Thibaut.

## Critères d'acceptation

```gherkin
Fonctionnalité: Liens vers la démo et le profil dans les 24 README

  Scénario: Les 24 README portent les deux liens (nominal)
    Étant donné l'URL du profil fournie
    Quand l'outil complète le bloc standard
    Alors les 24 README EN et FR contiennent un lien vers la démo et un lien vers le profil, identiques partout

  Scénario: Dépôt déjà traité (alternatif)
    Étant donné un dépôt dont le bloc est à jour
    Quand l'outil est relancé
    Alors le diff est vide

  Scénario: Plugin sans démo (alternatif)
    Étant donné un plugin absent de la démo (ex. plugin purement technique)
    Quand l'outil complète son README
    Alors seul le lien vers le profil est ajouté

  Scénario: URL de profil absente (erreur)
    Étant donné aucune URL fournie
    Quand l'outil est lancé
    Alors il refuse de modifier quoi que ce soit

  Scénario: Terme commercial ou lien mort (erreur)
    Étant donné un bloc contenant « mission », « devis », « prestation » ou un lien qui ne répond pas
    Quand le contrôle de liens et de ton est lancé
    Alors le dépôt est signalé et la PR n'est pas ouverte
```
