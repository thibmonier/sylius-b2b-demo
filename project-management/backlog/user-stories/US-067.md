# US-067 — README FR du lot B (12 plugins) et livraison des 24 dépôts

> Epic : [EPIC-09](../epics/EPIC-09.md) · Persona : Thibaut · MoSCoW : **Must** · Points : **3** · Sprint : 13
> Dépendances : US-064 (bloc standard, outil) ; découpée d'US-064 pour respecter le maximum de 8 points

## Story

En tant que Thibaut, je veux les 12 derniers `README.fr.md` et la livraison des 24 dépôts (branches prêtes, PR sur mon GO), afin que la bascule publique de la démo trouve tous les plugins bilingues et renvoyant à la démo.

## Contexte

Suite d'US-064 : même bloc, même outil, mêmes contrôles. Lot B : de `gpsr` à `withdrawal` (12 plugins). La livraison suit l'option retenue par l'utilisateur (PR par dépôt, recommandée, ou commit direct). La CI de beaucoup de plugins ignore les `*.md` : l'état des contrôles exigés est relevé avant le GO. Rien n'est poussé sans GO explicite.

## Périmètre

- `README.fr.md` des 12 plugins du lot B ; bloc standard et liens croisés via l'outil d'US-064.
- Contrôle des 24 dépôts avec `bin/vitrine-readme --check`.
- Une branche locale `docs/readme-fr-demo` par dépôt, commit conventionnel (`docs(readme): add French README and demo reference`), partie de `main` à jour.
- Note de GO : liste des 24 branches, état de la CI attendu, ordre de merge. Ouverture des PR et merge : par Claude **après le GO explicite** de l'utilisateur (calendaire).
- Hors périmètre : images (US-065), liens vers le site (US-068), publication de nouvelles versions des plugins (pas de tag).

## Critères d'acceptation

```gherkin
Fonctionnalité: Livraison des 24 README bilingues

  Scénario: Les 24 dépôts passent le contrôle (nominal)
    Étant donné les lots A et B traités
    Quand bin/vitrine-readme --check est lancé sur les 24 dépôts
    Alors les 24 dépôts sont conformes (README.fr.md, bloc, liens croisés)
    Et aucun lien vers le site ni la page contact n'est présent

  Scénario: Chaque dépôt a une branche propre prête à pousser (alternatif)
    Étant donné un dépôt qui était sur une branche de travail non mergée
    Quand la branche docs/readme-fr-demo est créée
    Alors elle part de main à jour après un git fetch
    Et elle ne contient que les fichiers de documentation

  Scénario: Les PR sont ouvertes sur GO (alternatif)
    Étant donné le GO explicite de l'utilisateur pour le lot
    Quand les branches sont poussées et les PR ouvertes
    Alors il y a 24 PR avec le même texte, et le merge attend un second GO

  Scénario: Un contrôle exigé reste en attente à cause de paths-ignore (erreur)
    Étant donné un dépôt dont la CI ignore les *.md et dont la branche exige ce contrôle
    Quand la PR est ouverte
    Alors le blocage est signalé à l'utilisateur dans la note de GO
    Et aucun contournement n'est appliqué sans son accord

  Scénario: Le dépôt n'est pas sur main ou n'est pas propre (erreur)
    Étant donné un dépôt avec des modifications non commitées
    Quand la branche est préparée
    Alors le dépôt est ignoré et signalé
    Et ses fichiers ne sont pas touchés
```
