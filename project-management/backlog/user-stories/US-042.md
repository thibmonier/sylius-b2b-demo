# US-042 — Routes restreintes configurables dans channel-access

> Epic : [EPIC-04](../epics/EPIC-04.md) · Persona : Thibaut · MoSCoW : **Should** · Points : **5** · Sprint : 8
> Dépendances : US-019, US-020

## Story

En tant que Thibaut, je veux lister dans la configuration du plugin channel-access les routes (ou motifs) refusées aux visiteurs qui ne peuvent pas voir les prix ou le catalogue, afin que la démo n'ait plus besoin d'une passe de compilation pour étendre cette liste.

## Contexte

Rétro du sprint 7. Le plugin `sylius-channel-access-plugin` (0.1.0) fige ses routes restreintes dans `TmonierSyliusChannelAccessExtension` (constantes `RESTRICTED_ROUTES` et `RESTRICTED_PATHS`) ; la démo les complète par `src/DependencyInjection/Compiler/RestrictPriceRoutesPass.php` (devis, commande rapide, MCP, prix dégressifs), qui réécrit les paramètres `tmonier_channel_access.restricted_routes` et `restricted_paths`. Le plugin a déjà des options `exempt_routes` et `exempt_paths` : les options symétriques `restricted_routes` et `restricted_paths` sont ajoutées, fusionnées avec les valeurs intégrées. La démo remplace sa passe par cette configuration. Publication de la version 0.2.0 après GO explicite de l'utilisateur.

## Critères d'acceptation

```gherkin
Fonctionnalité: Routes restreintes configurables

  Scénario: Route configurée refusée en mode prix masqués
    Étant donné la configuration restricted_routes contenant "tmonier_quote_request_shop_new" et un visiteur qui ne peut pas voir les prix
    Quand il demande cette route
    Alors l'accès est refusé comme pour le panier (redirection vers la connexion)
    Et la démo n'a plus de passe de compilation RestrictPriceRoutesPass

  Scénario: Motif avec joker
    Étant donné la configuration restricted_routes contenant "tmonier_b2b_mcp_shop_*"
    Quand un visiteur sans accès aux prix demande une route correspondant au motif
    Alors l'accès est refusé

  Scénario: Chemin d'API restreint
    Étant donné restricted_paths contenant ".../product-variants/*/tier-prices" et un visiteur sans accès aux prix
    Quand il demande ce chemin
    Alors la réponse est un refus (401 ou 403)

  Scénario: Valeur de configuration invalide
    Étant donné une configuration restricted_routes contenant une valeur vide ou non textuelle
    Quand le conteneur est compilé
    Alors une erreur de configuration explicite nomme l'option, sans route silencieusement ignorée

  Scénario: Route exemptée et restreinte à la fois
    Étant donné une route présente dans exempt_routes et dans restricted_routes
    Quand le conteneur est compilé
    Alors la compilation échoue avec un message nommant la route en conflit

  Scénario: Publication sans GO
    Étant donné la version validée sans GO explicite de l'utilisateur
    Alors aucun tag 0.2.0 ni version Packagist n'est publié et la démo garde sa passe actuelle
```

## Critères SMART

- **Spécifique** : deux options (`restricted_routes`, `restricted_paths`) fusionnées avec les routes intégrées, sans changer le comportement par défaut.
- **Mesurable** : 5 scénarios automatisés ; `RestrictPriceRoutesPass` supprimée, non-régression du `HardeningTest`.
- **Atteignable** : symétrique d'`exempt_routes`, ≈ 3 points.
- **Réaliste** : sans migration ni interface.
- **Temporel** : fin du sprint 8 (2026-10-30), publication selon le GO.

## Notes

Compatibilité ascendante : sans option, les routes intégrées s'appliquent seules. Retrait de la passe de la démo après publication (ou chemin local en l'absence de GO). Publication après GO explicite de l'utilisateur.
