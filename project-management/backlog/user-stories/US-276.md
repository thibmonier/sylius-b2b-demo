# US-276 — apexcharts 8 pour le graphique des statistiques de l'admin

> Epic : [EPIC-10](../epics/EPIC-10.md) · Persona : Sophie (back-office du marchand) · MoSCoW : **Should** · Points : **2** · Sprint : sprint 52 (planifié le 2026-11-10) · Statut : **ready-for-dev**
> Origine : veille des versions de la semaine 46 (#178).

## Story

En tant que Sophie, je veux que le graphique des statistiques du tableau de bord de l'admin reste identique après la montée d'apexcharts, afin de lire mes ventes sans régression.

## Contexte

- La démo requiert `apexcharts ^3.41.0` (version 3.54.1 installée) ; la dernière majeure est la 8.8.1 (cinq majeures d'écart).
- Un seul usage : `assets/admin/scripts/statistics_chart.js` (graphique du tableau de bord, couleurs lues dans les variables CSS de Tabler, mode clair ou sombre suivant `data-bs-theme`).
- Les options retirées ou renommées entre la 3 et la 8 sont à relever dans les notes de version avant le code.

## Critères d'acceptation

```gherkin
Fonctionnalité: Graphique des statistiques sur apexcharts 8

  Scénario: Rendu du tableau de bord (nominal)
    Étant donné la démo sur apexcharts 8
    Quand Sophie ouvre le tableau de bord de l'admin
    Alors le graphique s'affiche avec les mêmes séries, couleurs et axes qu'avant (captures avant/après)

  Scénario: Mode sombre de l'admin (alternatif)
    Étant donné l'admin en data-bs-theme="dark"
    Quand le graphique s'affiche
    Alors il utilise le mode sombre, comme avant

  Scénario: Changement de période (alternatif)
    Étant donné le graphique affiché
    Quand Sophie change la période des statistiques
    Alors le graphique est redessiné sans doublon

  Scénario: Option retirée (erreur)
    Étant donné une option d'apexcharts 3 retirée en 8
    Quand le build ou le navigateur la rencontre
    Alors elle est migrée, sans épingler l'ancienne version

  Scénario: Erreur JavaScript (erreur)
    Étant donné la page du tableau de bord
    Quand elle se charge
    Alors la console du navigateur ne contient aucune erreur
```
