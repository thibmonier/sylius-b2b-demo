# US-273 — Thème Industrie & Négoce : installation vérifiée dans un projet vierge par la CI

> Epic : [EPIC-18](../epics/EPIC-18.md) · Persona : Hugo (intégrateur Sylius) · MoSCoW : **Should** · Points : **2** · Sprint : sprint 51 (planifié le 2026-11-05) · Statut : **review** (thème #21)
> Origine : revue du sprint 50. La démo ne bascule pas sur le thème (décision de Thibaut du 2026-11-05) : l'installation du thème doit être prouvée ailleurs (reprise de T-228-09).

## Story

En tant qu'Hugo, je veux que la CI du thème installe le paquet dans un projet Sylius vierge en suivant le README, afin d'être sûr que la procédure documentée fonctionne telle quelle.

## Contexte

Le thème est publié sur Packagist (v0.1.0). La v0.1.1 corrige la cohabitation avec une application hôte (PR #20 du thème). Aucune CI ne suit aujourd'hui le README de bout en bout : copie des deux éléments de configuration, intégration des styles, activation par le `theme_name` du canal. Le job tourne sur Sylius 2.2 et 2.3, sur la branche et chaque lundi avec le test de dérive.

## Critères d'acceptation

```gherkin
Fonctionnalité: Installation du thème dans un projet vierge

  Scénario: Procédure du README (nominal)
    Étant donné un projet Sylius vierge créé par la CI
    Quand les commandes du README sont exécutées telles quelles
    Alors la page d'accueil répond 200 avec le marqueur du thème sur le canal configuré

  Scénario: Canal sans le thème (alternatif)
    Étant donné le même projet avec un second canal sans theme_name
    Quand sa page d'accueil est demandée
    Alors elle répond 200 sans le marqueur du thème

  Scénario: Les deux versions de Sylius (alternatif)
    Étant donné la matrice Sylius 2.2 et 2.3
    Quand le job tourne
    Alors il passe sur les deux

  Scénario: README modifié sans la CI (erreur)
    Étant donné une commande du README qui ne fonctionne plus
    Quand le job tourne
    Alors il échoue en nommant l'étape

  Scénario: Configuration oubliée (erreur)
    Étant donné que config/twig_hooks/ n'est pas copié
    Quand le job tourne
    Alors il échoue sur une assertion de rendu, pas sur une erreur de démarrage masquée
```

### Validation INVEST

### Constats de la réalisation

- Un Sylius-Standard neuf n'a pas de feuille de style shop : le README documente maintenant l'import depuis `assets/shop/entrypoint.js`.
- Sylius-Standard 2.2 déclare `FOSRestBundle` sans le requérir (il venait de `sylius/resource-bundle`, qui ne le requiert plus depuis 1.14) : le job l'ajoute à la création du projet, hors procédure du thème.
- Sans `twig_hooks` copié, le noyau refuse de démarrer (import manquant) : l'échec est nommé à l'étape « Boot the kernel », pas sur une assertion de rendu. Sans `copy-config` entier, l'échec est bien une assertion de rendu (liste produits).
- Le « second canal » est une copie SQL du canal des fixtures (`tests/BlankProject/channels.sql`), choisi par nom d'hôte.
