# US-181 — Plugin b2b-mcp : dépendance `symfony/lock` et import des routes du serveur MCP

> Epic : [EPIC-14](../epics/EPIC-14.md) · Persona : lead développeur d'une agence · MoSCoW : **Should** · Points : **1** · Sprint : backlog
> Origine : installation réelle du pack « IA et headless » en CI (US-176, sprint 25, 2026-10-24)

## Story

En tant que lead développeur, je veux installer le plugin b2b-mcp en suivant son README sans dépendance manquante ni erreur du routeur, afin de ne pas déboguer l'installation d'un plugin publié.

## Contexte

Deux défauts trouvés par la CI des packs, dans le dépôt `thibmonier/sylius-b2b-mcp-plugin` (non modifié au sprint 25) :

| Défaut | Effet | Contournement actuel |
|---|---|---|
| `symfony/lock` absent du `require` alors que le limiteur de débit du plugin en a besoin | Conteneur qui ne compile pas dans un projet sans `symfony/lock` | Le pack « IA et headless » ajoute `composer require symfony/lock` à ses gestes |
| Le README fait importer les routes du serveur MCP, que la recette Flex de `sylius/mcp-server-plugin` importe déjà | « Do not add the mcp loader twice » : le routeur échoue | Le README du pack dit de ne pas répéter l'import |

### Validation INVEST

- [x] Independent / Negotiable / Valuable / Estimable ≈ 2 h / Sized 1 / Testable

## Prérequis d'environnement

Travail dans le dépôt du plugin (arbre principal, pas de worktree isolé). CI du plugin comme juge ; aucune installation lourde en local sous 6 Go libres.

## Versions et publication

Version corrective du plugin (tag et release sur GO de Thibaut). Ensuite, retrait du geste `symfony/lock` du pack « IA et headless » si la borne du pack couvre la version corrigée.

## Critères d'acceptation

```gherkin
Fonctionnalité: Installation du plugin b2b-mcp sans défaut

  Scénario: Dépendance déclarée (nominal)
    Étant donné un projet Sylius sans symfony/lock
    Quand le plugin b2b-mcp est installé par Composer
    Alors symfony/lock est installé avec lui et le conteneur compile

  Scénario: Projet avec Flex (alternatif)
    Étant donné un projet qui applique la recette de sylius/mcp-server-plugin
    Quand les gestes du README du plugin sont suivis
    Alors les routes du serveur MCP ne sont importées qu'une fois et le routeur se charge

  Scénario: Projet sans Flex (alternatif)
    Étant donné un projet qui n'applique pas les recettes Flex
    Quand les gestes du README du plugin sont suivis
    Alors le README dit d'importer les routes du serveur MCP, et le routeur se charge

  Scénario: Import en double (erreur)
    Étant donné un README qui fait de nouveau importer les routes déjà importées par la recette
    Quand la CI applique ses gestes
    Alors elle échoue en nommant l'étape

  Scénario: Pack inchangé (erreur)
    Étant donné le pack « IA et headless » après la correction
    Quand sa CI d'installation tourne
    Alors elle reste verte, avec ou sans le geste symfony/lock selon la borne du pack
```
