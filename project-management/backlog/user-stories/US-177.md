# US-177 — Recettes Symfony Flex des packs

> Epic : [EPIC-14](../epics/EPIC-14.md) · Persona : lead développeur d'une agence · MoSCoW : **Could** · Points : **5** · Sprint : backlog (après US-176 et la publication des packs)
> Origine : ADR 0015 accepté par Thibaut le 2026-10-23 (spike US-173), story 3 de la réalisation

## Story

En tant que lead développeur, je veux qu'installer un pack déclare aussi ses bundles, sa configuration et ses routes, afin que le pack soit vraiment clé en main.

## Contexte

Une recette Flex par métapaquet : bundles, `config/packages`, `config/routes`. Point non vérifié par le spike (question ouverte 3 de l'ADR) : Flex applique-t-il une recette à un métapaquet venu de Packagist ? À tester dans un projet jetable avant toute pull request. La pull request sur `symfony/recipes-contrib` est publique : ouverte seulement avec l'accord de Thibaut (question ouverte 4).

### Validation INVEST

- [x] Independent / Negotiable / Valuable / Estimable / Sized 5 / Testable

## Prérequis d'environnement

Packs publiés sur Packagist (US-175, GO de Thibaut) ; installation réelle verte (US-176).

## Versions et publication

Pull request publique sur `symfony/recipes-contrib` : seulement après GO de Thibaut.

## Critères d'acceptation

```gherkin
Fonctionnalité: Recettes des packs

  Scénario: Pack installé sans geste manuel (nominal)
    Étant donné un projet Sylius vierge avec Flex
    Quand le pack est installé
    Alors bundles, configuration et routes sont déclarés et la CI d'US-176 passe sans appliquer les gestes du README

  Scénario: Désinstallation propre (alternatif)
    Étant donné un pack installé par sa recette
    Quand il est retiré
    Alors la recette retire ce qu'elle a ajouté

  Scénario: Recette non appliquée à un métapaquet (alternatif)
    Étant donné que Flex n'applique pas une recette à un métapaquet
    Quand l'essai le montre
    Alors la story s'arrête, le README garde les gestes manuels et l'ADR 0015 est mis à jour

  Scénario: Fichier de l'application déjà présent (erreur)
    Étant donné un fichier de configuration déjà présent dans le projet
    Quand la recette s'applique
    Alors elle ne l'écrase pas

  Scénario: Publication sans accord (erreur)
    Étant donné une recette prête
    Quand l'accord de Thibaut manque
    Alors aucune pull request n'est ouverte sur recipes-contrib
```
