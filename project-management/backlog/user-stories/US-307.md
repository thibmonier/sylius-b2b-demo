# US-307 — Commande `tmonier:health:check` : sortie texte ou JSON, code de sortie 0/1/2, filtres

> Origine : EPIC-23. Question de Thibaut du 2026-11-26 : comment voir la santé depuis la console de Railway. Dépend d'[US-288](US-288.md) (exécuteur). Suit US-303 dans le même dépôt.

## Story

En tant que DSI, je veux lancer le diagnostic de santé en ligne de commande et obtenir un code de sortie qui a un sens, afin de m'en servir comme porte de recette dans la CI après un déploiement, dans un cron, ou depuis la console de l'hébergeur sans ouvrir l'administration.

## Contexte

- La commande exécute les sondes **par l'exécuteur** (`HealthCheckRunner`), avec le même budget de temps et le même masquage que la page. Elle ne lit pas le cache partagé : un diagnostic en console doit être frais. Elle n'écrit rien.
- **Sortie texte** (par défaut) : une ligne par sonde (statut écrit, identifiant, résumé), regroupée par catégorie, puis une ligne de synthèse.
- **Sortie JSON** (`--format=json`) : `{"status": "...", "generated_at": "...", "checks": [{"identifier", "category", "status", "summary"}]}`. Pas de détail, pas de lien.
- **Filtres** : `--category=data` (répétable), `--only=data.connection` (répétable).
- Textes dans la locale par défaut de l'application ; aucune valeur que la page masque n'apparaît ici.

### Code de sortie : tableau de cas aux bornes (A-58-4)

| Résultats retenus après filtres | Code |
|---|---|
| toutes les sondes `ok` | **0** |
| au moins une `warning`, aucune `critical` | **1** |
| au moins une `unknown`, aucune `critical` (décision de Thibaut du 2026-11-26 : une sonde qui ne mesure pas ne passe pas une porte de CI en silence) | **1** |
| au moins une `critical`, quelles que soient les autres | **2** |
| une seule sonde, `critical` | **2** |
| option invalide : `--category` inconnue, `--only` qui ne désigne aucune sonde, `--format` inconnu | **3**, avec un message qui nomme la valeur refusée (distinct de 2 : une faute de frappe dans la CI ne doit pas se lire comme « critique ») |
| aucune sonde après filtres valides (catégorie connue mais vide) | **0**, avec le message « aucune sonde » |

## Critères d'acceptation

```gherkin
Fonctionnalité: Diagnostic de santé en console

  Scénario: Tout va bien (nominal)
    Étant donné des sondes toutes « ok »
    Quand je lance « tmonier:health:check »
    Alors la sortie liste chaque sonde avec son statut écrit
    Et le code de sortie est 0

  Scénario: JSON filtré (alternatif)
    Étant donné une sonde « data.connection » en « warning »
    Quand je lance « tmonier:health:check --format=json --only=data.connection »
    Alors la sortie est un JSON valide qui ne contient que cette sonde
    Et le code de sortie est 1

  Scénario: Une sonde critique parmi d'autres (alternatif)
    Étant donné une sonde « critical », une « unknown » et des « ok »
    Quand je lance la commande
    Alors le code de sortie est 2

  Scénario: Sonde qui lève une exception (erreur)
    Étant donné une sonde qui lève une exception
    Quand je lance la commande
    Alors elle apparaît en « unknown » sans trace de pile, la cause est journalisée
    Et le code de sortie est 1

  Scénario: Filtre invalide (erreur)
    Étant donné aucune sonde « data.inconnue »
    Quand je lance « tmonier:health:check --only=data.inconnue »
    Alors le message nomme « data.inconnue »
    Et le code de sortie est 3
```
