# US-172 — Guide de surcharge des plugins

> Epic : [EPIC-12](../epics/EPIC-12.md) · Persona : lead développeur d'une agence · MoSCoW : **Should** · Points : **3** · Sprint : cible sprint 24
> Origine : critique du 2026-10-23 (architecte Sylius et client B2B) ; décision de Thibaut du même jour

## Story

En tant que développeur d'une agence, je veux savoir comment adapter un plugin sans le modifier, afin de l'intégrer à un projet client et de garder les mises à jour possibles.

## Contexte

La démo surcharge déjà plusieurs plugins : ce sont des exemples réels à documenter, pas des exemples inventés. Le guide couvre quatre cas, chacun avec un exemple pris dans la démo (fichier et lignes) et une commande de vérification :

| Cas | Mécanisme |
|---|---|
| Template | Twig hooks de Sylius 2, surcharge de gabarit de bundle |
| Formulaire | Extension de type de formulaire |
| Entité | Modèle Sylius surchargé (`sylius_resource`), `resolve_target_entities` pour les interfaces des plugins |
| Service | Décoration de service, liaisons typées (exemple : les limiteurs de débit d'US-148) |

Le guide vit dans la démo (page ou `docs/`, décidé au cadrage) ; chaque README de plugin y renvoie pour les cas propres au plugin.

### Validation INVEST

- [x] Independent / Negotiable / Valuable / Estimable ≈ 6 h / Sized 3 / Testable

## Prérequis d'environnement

Aucun.

## Versions et publication

Liens ajoutés aux README des plugins : une PR par dépôt de plugin, sans tag, après GO de Thibaut.

## Critères d'acceptation

```gherkin
Fonctionnalité: Guide de surcharge

  Scénario: Quatre cas documentés (nominal)
    Étant donné le guide de surcharge
    Quand un développeur le lit
    Alors il trouve pour le template, le formulaire, l'entité et le service un exemple réel de la démo et une commande de vérification

  Scénario: Exemple vérifiable (alternatif)
    Étant donné un exemple du guide
    Quand le développeur suit le lien
    Alors il arrive sur le fichier exact de la démo, et un test vérifie que ce fichier existe toujours

  Scénario: Renvoi depuis un README de plugin (alternatif)
    Étant donné le README d'un plugin qui a des points d'extension
    Quand le développeur le lit
    Alors il trouve un lien vers le guide

  Scénario: Exemple devenu faux (erreur)
    Étant donné un fichier cité par le guide, renommé ou supprimé
    Quand la suite s'exécute
    Alors le test du guide échoue avec le chemin manquant

  Scénario: Surcharge qui casse une mise à jour (erreur)
    Étant donné une surcharge qui copie un gabarit entier
    Quand le guide la présente
    Alors il la signale comme dernier recours et propose d'abord un hook ou une extension
```
