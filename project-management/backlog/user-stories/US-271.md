# US-271 — Couverture de tests du plugin predictive-analytics (78,36 % → ≥ 80 %)

> Epic : [EPIC-12](../epics/EPIC-12.md) · Persona : Camille (recruteuse) · MoSCoW : **Should** · Points : **2** · Sprint : sprint 50 (planifié le 2026-11-05) · Statut : **ready-for-dev**
> Origine : fin d'US-253 (sprint 48) : taux mesuré le 2026-11-04 sur `main` (78,36 % des lignes, check run [126805587231](https://github.com/thibmonier/sylius-b2b-predictive-analytics-plugin/runs/126805587231)). Proposition validée par Thibaut le 2026-11-04.

## Story

En tant que recruteuse, je veux que le plugin predictive-analytics atteigne au moins 80 % de couverture des lignes, afin de le comparer aux autres plugins de la page « Preuve technique » sur une base équivalente.

## Contexte

Le taux réel est publié sur la page « Preuve technique » (aucun masquage). Les tests ajoutés ciblent les comportements non couverts, repérés dans le rapport Clover de la CI (`build/coverage.xml`, étape « PHPUnit line coverage » sur `main`), en commençant par les classes de `src/` les moins couvertes. Pas de test écrit pour le seul chiffre : chaque test vérifie un comportement observable.

## Critères d'acceptation

```gherkin
Fonctionnalité: Couverture du plugin predictive-analytics

  Scénario: Seuil atteint (nominal)
    Étant donné les tests ajoutés mergés sur main
    Quand le check run « coverage » est publié
    Alors il affiche au moins 80 % des lignes

  Scénario: Preuve technique à jour (alternatif)
    Étant donné le nouveau taux publié
    Quand bin/proof-refresh est lancé dans la démo
    Alors la tuile du plugin affiche ce taux, avec le lien vers le check run

  Scénario: Comportement d'erreur couvert (alternatif)
    Étant donné une branche d'erreur non couverte de src/
    Quand son test est écrit
    Alors il vérifie le message ou l'état observable, pas seulement l'absence d'exception

  Scénario: Test vacant (erreur)
    Étant donné un test sans assertion de comportement (assertTrue(true), markTestIncomplete)
    Quand la PR est relue
    Alors elle est refusée

  Scénario: Seuil manqué (erreur)
    Étant donné un taux final sous 80 %
    Quand la story est revue
    Alors le taux réel est publié et l'écart est expliqué à Thibaut, sans exclure de code de la mesure
```
