# US-176 — Installation réelle d'un pack en CI

> Epic : [EPIC-14](../epics/EPIC-14.md) · Persona : lead développeur d'une agence ; Thibaut · MoSCoW : **Should** · Points : **5** · Sprint : backlog (après US-175)
> Origine : ADR 0015 accepté par Thibaut le 2026-10-23 (spike US-173), story 2 de la réalisation

## Story

En tant que Thibaut, je veux que la CI installe chaque pack dans un projet Sylius vierge, afin de prouver qu'il fonctionne réellement et pas seulement qu'il se résout.

## Contexte

Le spike n'a fait qu'une résolution Composer, sans `vendor/`. Cette story installe vraiment : projet Sylius vierge, `composer require` du métapaquet, gestes du README appliqués, migrations, `lint:container`, `doctrine:schema:validate`. Matrice Sylius 2.2 et 2.3 (plancher commun : PHP 8.2, Sylius 2.2).

### Validation INVEST

- [x] Independent / Negotiable / Valuable / Estimable / Sized 5 / Testable

## Prérequis d'environnement

US-175 faite (métapaquets disponibles, dépôt `path` accepté en CI avant publication).

## Versions et publication

CI des dépôts de packs ; aucune publication.

## Critères d'acceptation

```gherkin
Fonctionnalité: Installation réelle d'un pack

  Scénario: Pack installé et démarré (nominal)
    Étant donné un projet Sylius vierge
    Quand la CI installe le pack et applique les gestes du README
    Alors les migrations passent, lint:container et doctrine:schema:validate réussissent

  Scénario: Matrice de versions (alternatif)
    Étant donné Sylius 2.2 et Sylius 2.3
    Quand la CI tourne
    Alors le pack s'installe sur les deux, ou l'écart est écrit dans le README

  Scénario: Les deux packs ensemble (alternatif)
    Étant donné les deux packs installés dans le même projet
    Quand la CI tourne
    Alors le conteneur se compile sans conflit de service ni de route

  Scénario: Membre qui casse l'installation (erreur)
    Étant donné une nouvelle version d'un plugin qui casse l'installation
    Quand la CI tourne
    Alors elle échoue en nommant le plugin et l'étape

  Scénario: Geste du README faux (erreur)
    Étant donné un geste du README qui ne correspond plus au plugin
    Quand la CI l'applique
    Alors elle échoue et le README est corrigé avant la publication
```

## Definition of Done

- [ ] Chaque scénario relié à une preuve dans le fichier de tâches
- [ ] CI verte sur la matrice
- [ ] Ressources : une seule installation lourde à la fois en local, sinon CI
