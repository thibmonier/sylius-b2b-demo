# US-253 — Preuve technique : couverture de code publiée pour tous les plugins

> Epic : [EPIC-12](../epics/EPIC-12.md) · Persona : Camille (recruteuse) · MoSCoW : **Should** · Points : **5** · Sprint : non planifiée · Statut : **backlog**
> Dépendances : US-252 (mécanisme validé et outils écrits sur 3 plugins)
> Origine : demande de Thibaut du 2026-10-31 (couverture pour l'ensemble des plugins)

## Story

En tant que recruteuse, je veux la couverture de code de chaque plugin présenté dans la démo, afin de comparer leur niveau de test sur une même base.

## Contexte

US-252 a écrit l'étape de CI et le script de publication, puis les a éprouvés sur la démo et 3 plugins. Il reste les 27 autres plugins présentés. Comme le durcissement de la chaîne d'approvisionnement du 2026-10-28 (`bin/plugin-supply-chain`), le déploiement se fait par un script idempotent. Le script ajoute l'étape à chaque dépôt et ouvre une PR par dépôt. Il fonctionne par lots de 5 dépôts au plus, pour respecter la règle « un push puis attendre » et ménager la machine.

Les dépôts dont la CI échoue une fois la couverture activée (pcov absent, tests trop lents) sont listés et traités un par un, jamais contournés. Les taux mesurés sont reportés à Thibaut avant leur publication sur la page : un taux bas peut motiver une story de tests, mais il n'est jamais masqué.

## Critères d'acceptation

```gherkin
Fonctionnalité: Couverture publiée pour tous les plugins

  Scénario: Tous les plugins mesurés (nominal)
    Étant donné les 30 plugins de config/demo/proof.json
    Quand le déploiement est terminé et bin/proof-refresh lancé
    Alors la tuile « Couverture de code » de la page « Preuve technique » affiche 30/30

  Scénario: Script relancé (alternatif)
    Étant donné un dépôt qui publie déjà sa couverture
    Quand le script de déploiement est relancé
    Alors il ne modifie pas ce dépôt et n'ouvre aucune PR

  Scénario: Taux bas (alternatif)
    Étant donné un plugin sous 80 % des lignes
    Quand les taux sont reportés à Thibaut
    Alors le taux réel est publié et une proposition de story de tests lui est faite

  Scénario: CI en échec après activation (erreur)
    Étant donné un dépôt dont la CI échoue une fois la couverture activée
    Quand le lot est relu
    Alors sa PR n'est pas fusionnée, la cause est notée au registre et le dépôt est traité seul

  Scénario: Dépôt archivé ou sans CI (erreur)
    Étant donné un dépôt archivé ou sans workflow de CI
    Quand le script le rencontre
    Alors il le signale et passe au suivant sans rien écrire
```
