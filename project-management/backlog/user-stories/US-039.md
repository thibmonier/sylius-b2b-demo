# US-039 — Correctif du plugin container-fill

> Epic : [EPIC-07](../epics/EPIC-07.md) · Persona : Thibaut · MoSCoW : **Should** · Points : **3** · Sprint : 7
> Dépendances : US-026

## Story

En tant que Thibaut, je veux que container-fill ignore les lignes de panier sans données logistiques, afin qu'une règle « tous produits » ne bloque plus les paniers mixtes.

## Contexte

Constat R5 de `sprints/sprint-3-nouveaux-plugins/review-findings.md` : aucun impact aujourd'hui (aucune règle chargée), correctif préventif.

## Critères d'acceptation

```gherkin
Fonctionnalité: Correctif du plugin container-fill

  Scénario: Ligne sans données logistiques
    Étant donné une règle « tous produits » et un panier avec une ligne sans poids ni volume
    Quand la règle est évaluée
    Alors la ligne est ignorée et le panier n'est pas bloqué

  Scénario: Lignes avec données logistiques
    Étant donné un panier dont toutes les lignes ont poids et volume
    Quand la règle est évaluée
    Alors le calcul de remplissage est inchangé

  Scénario: Panier sans aucune donnée logistique
    Étant donné un panier dont aucune ligne n'a de données logistiques
    Quand la règle est évaluée
    Alors le panier est accepté sans erreur de division ni exception

  Scénario: Données partielles invalides
    Étant donné une ligne avec un poids nul ou négatif
    Quand la règle est évaluée
    Alors la ligne est ignorée (ou rejetée explicitement) sans exception non gérée

  Scénario: Donnée logistique corrompue
    Étant donné une règle « tous produits » et une ligne dont le volume n'est pas un nombre (valeur importée corrompue)
    Quand la règle est évaluée
    Alors la ligne est écartée du calcul avec un avertissement journalisé nommant la variante
    Et aucune exception n'interrompt le panier ni le checkout

  Scénario: Publication sans GO
    Étant donné le correctif validé mais sans GO explicite de l'utilisateur
    Alors aucun tag ni version Packagist n'est publié
```

## Notes

Publication après GO explicite de l'utilisateur.
