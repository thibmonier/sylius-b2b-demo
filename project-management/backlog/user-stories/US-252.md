> Epic : [EPIC-12](../epics/EPIC-12.md) · Persona : Camille (recruteuse) ; Thibaut (démonstrateur) · MoSCoW : **Should** · Points : **5** · Sprint : non planifiée · Statut : **backlog**

## Story

En tant que recruteuse, je veux lire la couverture de code de la démo et de chaque plugin sur la page « Preuve technique », avec sa source, afin de vérifier la qualité annoncée plutôt que de la croire.

## Contexte

État au 2026-10-31 :
- **La démo** mesure déjà sa couverture en CI (pcov, `bin/check-coverage`, blocage sous 90 % des lignes) : **93,31 % des lignes** (6434 sur 6895), 84,42 % des méthodes, sur le run 41182351481. Le chiffre ne sort que dans le résumé du job et n'apparaît pas sur la page « Preuve technique ».
- **Les 30 plugins présentés** ne mesurent pas leur couverture : `SyliusLabs/BuildTestAppAction` est appelée avec `php_coverage: none`, la valeur par défaut.
- **La page « Preuve technique »** a déjà une tuile et une colonne « Couverture ». Elle n'affiche une valeur que si une source publique la donne : `ProofCollector` n'écrit jamais de couverture, d'où le texte « Aucune source publique n'en donne le chiffre : elle n'est jamais estimée ».

Il faut donc une **source publique, lisible sans jeton**, que `ProofCollector` interroge comme il interroge déjà l'API GitHub. Proposition à valider en première tâche : la CI publie le taux dans un **check run** dédié (`coverage`, résumé `Lines: 93.31 %`), lisible par l'API REST publique des check runs du dernier commit de `main`. Ce choix n'ajoute aucun service externe ni jeton tiers. Codecov est écarté par défaut, car il ajoute un service et un jeton tiers dans 31 dépôts (règle 11, chaîne d'approvisionnement).

Le pilote porte sur la démo et 3 plugins : le copilote, le passeport et le parc (customer-asset-management), où un seul cas de la matrice CI mesure la couverture. Les outils du pilote (étape de CI, script de publication) sont écrits pour être recopiés tels quels par US-253.

**Décision de Thibaut du 2026-10-31** : sur la page publique, le chiffre réel est affiché même s'il est bas (pas de seuil d'affichage), conformément au principe de la page (« jamais estimé »). Aucun seuil bloquant n'est ajouté aux plugins dans cette story : on mesure d'abord.

## Critères d'acceptation

```gherkin
Fonctionnalité: Couverture de code sur la page « Preuve technique »

  Scénario: Couverture d'un plugin affichée avec sa source (nominal)
    Étant donné un plugin du pilote dont la CI de main a publié son check run « coverage »
    Quand bin/proof-refresh tourne puis qu'une visiteuse ouvre la page « Preuve technique »
    Alors la colonne « Couverture » donne le taux de lignes, la date du relevé et un lien vers le run

  Scénario: Couverture de la démo (nominal)
    Étant donné la CI de main de la démo
    Quand la page « Preuve technique » est affichée
    Alors la section de livraison de la démo donne son taux de lignes (93,31 % au 2026-10-31) avec le lien vers le run

  Scénario: Plugin sans mesure (alternatif)
    Étant donné un plugin hors du pilote
    Quand la page est affichée
    Alors sa cellule indique « non publiée », sans aucune estimation

  Scénario: Source en échec (erreur)
    Étant donné l'API GitHub qui ne répond pas pendant bin/proof-refresh
    Quand le relevé est enregistré
    Alors la dernière valeur vérifiée est conservée et marquée périmée

  Scénario: Résumé illisible (erreur)
    Étant donné un check run « coverage » dont le résumé ne contient pas de taux valide
    Quand bin/proof-refresh le lit
    Alors aucune valeur n'est écrite pour ce plugin et le relevé le signale
```
