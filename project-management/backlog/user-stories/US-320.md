# US-320 — Commande `tmonier:health:check` : seuil d'échec `--fail-on=warning|critical`

> Epic : [EPIC-23](../epics/EPIC-23.md) · Persona : Didier (DSI) ; Hugo (intégrateur Sylius) · MoSCoW : **Could** · Points : **2** · Sprint : à planifier · Statut : **backlog**
> Origine : revue du sprint 59 (2026-11-27). Thibaut garde le comportement actuel (option A : `unknown` donne 1, et une porte de CI filtre par catégorie) et fait inscrire l'option B au backlog. Dépend d'[US-307](US-307.md) (commande, v0.5.0). Dépôt : `sylius-platform-health-plugin`.

## Story

En tant qu'intégrateur qui place `tmonier:health:check` en porte de CI sur toutes les catégories, je veux choisir à partir de quel statut la commande échoue, afin qu'un déploiement ne soit pas bloqué par des sondes `unknown` (tâches planifiées qui n'ont pas encore tourné) quand je n'exige que l'absence de `critical`.

## Contexte

- Contrat publié en v0.5.0 : `0` tout est `ok` ; `1` au moins un `warning` ou un `unknown` ; `2` au moins un `critical` ; `3` option invalide. **Sans l'option, rien ne change.**
- `--fail-on=warning` (défaut implicite) : comportement actuel.
- `--fail-on=critical` : `warning` et `unknown` sortent en `0`, `critical` en `2`. La sortie texte ou JSON reste complète : seul le code de sortie change.
- Une valeur inconnue (`--fail-on=foo`) donne `3`, comme toute option invalide.
- Écarté : un code de sortie propre à `unknown`, qui casserait le contrat 0/1/2/3 (option C de la revue).

## Critères d'acceptation

```gherkin
Fonctionnalité: Seuil d'échec de la commande de santé

  Scénario: Seuil critique, sondes inconnues après un déploiement (nominal)
    Étant donné des sondes ok et deux sondes unknown
    Quand j'exécute "tmonier:health:check --fail-on=critical"
    Alors le code de sortie est 0
    Et la sortie liste toujours les deux sondes unknown

  Scénario: Seuil critique, sonde critique (alternatif)
    Étant donné une sonde critical
    Quand j'exécute "tmonier:health:check --fail-on=critical"
    Alors le code de sortie est 2

  Scénario: Sans l'option, contrat inchangé (alternatif)
    Étant donné une sonde unknown et aucune critical
    Quand j'exécute "tmonier:health:check"
    Alors le code de sortie est 1

  Scénario: Valeur invalide (erreur)
    Quand j'exécute "tmonier:health:check --fail-on=foo"
    Alors le code de sortie est 3
    Et le message liste les valeurs acceptées

  Scénario: Combinée au filtre de catégorie (erreur évitée)
    Étant donné une sonde critical hors de la catégorie data
    Quand j'exécute "tmonier:health:check --category=data --fail-on=critical"
    Alors le code de sortie ne tient compte que des sondes de data
```
