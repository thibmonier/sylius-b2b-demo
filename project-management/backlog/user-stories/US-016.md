# US-016 — Badges de plugin dans le shop

> Epic : [EPIC-03](../epics/EPIC-03.md) · Persona : Hugo · MoSCoW : **Must** · Points : **5** · Sprint : 4
> Dépendances : US-013

## Story

En tant que Hugo, je veux voir quelle fonctionnalité vient de quel plugin, afin d'évaluer chaque plugin.

## Valeur

Demande explicite de l'utilisateur.

## Critères d'acceptation

```gherkin
Fonctionnalité: Badges de plugin dans le shop

  Scénario: Badge (nominal)
    Quand une fonctionnalité de plugin est affichée (paliers, devis, quick-order, approbation…)
    Alors un badge (icône et infobulle « Plugin tmonier/… ») renvoie vers le plugin
    Et il est accessible au clavier

  Scénario: Désactivation (alternatif)
    Quand je masque les badges depuis le bandeau
    Alors ils disparaissent

  Scénario: Préférence conservée (alternatif)
    Quand j'ai masqué les badges puis je change de page
    Alors ils restent masqués jusqu'à ce que je les réaffiche

  Scénario: Registre complet (alternatif)
    Quand je liste les hooks de plugin du registre YAML
    Alors chacun référence un plugin existant dans la page Plugins

  Scénario: Hook absent du registre (erreur)
    Quand un hook de plugin affiché n'est pas dans le registre
    Alors aucun badge n'est rendu et aucune erreur n'est levée

  Scénario: Registre pointant vers un plugin inconnu (erreur)
    Quand une entrée du registre référence un plugin inexistant
    Alors le conteneur ou un test échoue en CI avec le nom de l'entrée
```

## Notes

Registre YAML hook → plugin ; badges neutres, sans imiter Sylius Plus.

Registre : `config/packages/demo_plugin_badges.yaml` (voir `tasks/US-016-tasks.md`). Préférence : cookie `demo_badges`, bascule dans le bandeau de démo.
