# US-268 — Passeport produit : QR codes avec endroid/qr-code 6

> Epic : [EPIC-10](../epics/EPIC-10.md) · Persona : Thibaut · MoSCoW : **Should** · Points : **2** · Sprint : sprint 48 · Statut : **done** (PR #18 du passeport, b2e301a)
> Origine : veille des versions du 2026-11-04 (PR Dependabot #17 de `sylius-digital-product-passport-plugin`, `endroid/qr-code ^5.0 → ^6.1`, rouge, fermée)

## Story

En tant que Thibaut, je veux que le plugin passeport produit génère ses QR codes avec endroid/qr-code 6, afin de rester sur la dernière majeure d'une dépendance utilisée à l'exécution.

## Contexte

endroid/qr-code 6 supprime la fabrique statique `Builder::create()`. `src/Service/DigitalLink/QrGenerator.php` l'utilise : PHPStan échoue (« Call to an undefined static method Endroid\QrCode\Builder\Builder::create() ») sur toutes les lignes de la matrice. En v6, le `Builder` se construit par son constructeur, avec des arguments nommés (writer, data, encoding, niveau de correction, taille, marge).

Contrairement à PHPUnit (US-266), cette montée ne dépend pas de Sylius : elle peut être faite dès qu'elle est planifiée. La PR a été fermée sans `ignore` : Dependabot la reproposera à la prochaine version 6.x.

## Critères d'acceptation

```gherkin
Fonctionnalité: QR codes du passeport avec endroid/qr-code 6

  Scénario: QR code PNG (nominal)
    Étant donné un produit avec un passeport publié
    Quand le QR code PNG du Digital Link est demandé
    Alors une image PNG est renvoyée et son décodage donne l'URL Digital Link du produit

  Scénario: QR code SVG (alternatif)
    Quand le QR code SVG est demandé
    Alors un SVG valide est renvoyé, avec la même URL encodée

  Scénario: Paramètres conservés (alternatif)
    Quand un QR code est généré
    Alors l'encodage, le niveau de correction, la taille et la marge sont ceux de la version 5

  Scénario: Passeport non publié (erreur)
    Étant donné un produit sans passeport publié
    Quand son QR code est demandé
    Alors la réponse est la même qu'avant la montée (aucune image générée)

  Scénario: Ancienne API (erreur évitée)
    Quand PHPStan analyse le plugin
    Alors aucun appel à `Builder::create()` ne subsiste
```
