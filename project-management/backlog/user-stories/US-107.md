# US-107 — Page « Intégrer ces plugins dans votre projet »

> Epic : [EPIC-12](../epics/EPIC-12.md) · Persona : Didier · MoSCoW : **Must** · Points : **5** · Sprint : cible sprint 17 (plan du 2026-10-20, ajustable au lancement du sprint)
> Dépendances : audit fonctionnel §6.2.3 (top 10 n°5) ; URL du site et de la page contact (paramètres de configuration)

## Story

En tant que Didier (DSI d'un distributeur), je veux une page qui explique comment ces plugins s'intègrent à un projet (formules, questions préalables, architecture type, délais indicatifs), afin d'évaluer l'effort et de contacter Thibaut en connaissance de cause.

## Contexte

Trois formules neutres : Cadrage, Intégration, Accompagnement. Questions préalables : ERP, PunchOut, facturation électronique, volumétrie. Pas de prix ni de comparaison avec une autre offre ; mention sobre du support sous contrat. Le formulaire de contact est externe (page contact du site).

## Critères d'acceptation

```gherkin
Fonctionnalité: Page « Intégrer ces plugins dans votre projet »

  Scénario: Page complète (nominal)
    Étant donné la page ouverte par Didier
    Quand il la lit
    Alors il voit trois formules, les questions préalables, une architecture type et des délais indicatifs

  Scénario: Bouton de contact (alternatif)
    Étant donné l'URL contact configurée
    Quand Didier clique sur « Échanger sur votre projet »
    Alors il arrive sur la page contact avec un paramètre de suivi de la page d'origine

  Scénario: Sans URL (alternatif)
    Étant donné aucune URL de contact
    Quand la page est affichée
    Alors le bouton est masqué et le reste de la page s'affiche

  Scénario: Mention interdite (erreur)
    Étant donné un texte comparatif ou promotionnel
    Quand le contrôle de charte s'exécute
    Alors il échoue
```

## Mise à jour du 2026-10-21 (repositionnement « recherche d'emploi »)

La page devient un **guide technique en libre-service** (US-158) : prérequis, installation, configuration, architecture type, questions d'intégration (ERP, PunchOut, facture électronique, volumétrie) traitées comme des points de conception. Les trois formules (Cadrage, Intégration, Accompagnement), les délais indicatifs, la mention de support sous contrat et le bouton « Échanger sur votre projet » sont retirés. Persona principale : Hugo (intégrateur) plutôt que Didier.

```gherkin
Scénario: Guide technique complet (remplace « Page complète »)
  Étant donné la page /integrer ouverte en FR puis en EN
  Quand Hugo la lit
  Alors il voit prérequis, étapes d'installation, configuration, architecture type et questions d'intégration, et aucune formule, aucun délai, aucun prix

Scénario: CTA neutre (remplace « Bouton de contact » et « Sans URL »)
  Étant donné DEMO_PROFILE_URL renseignée, puis vide
  Quand la page est affichée
  Alors le pied de page porte le lien vers le profil de l'auteur dans le premier cas et aucun lien dans le second
```
Le scénario « Mention interdite » reste valable : le contrôle de charte v2 s'applique.
