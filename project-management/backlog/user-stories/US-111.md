# US-111 — Bloc de preuve technique : qualité, compatibilité, versions

> Epic : [EPIC-12](../epics/EPIC-12.md) · Persona : Camille (recruteuse IT), Hugo · MoSCoW : **Should** · Points : **3** · Sprint : cible sprint 18 (replanifiée le 2026-10-21, repositionnement « recherche d'emploi »)
> Dépendances : audit fonctionnel §6.2.9 ; US-084

## Story

En tant que Camille, qui veut vérifier que la qualité reste intacte quand on livre avec l'IA, et Hugo (intégrateur), je veux un tableau qui indique pour chaque plugin sa version publiée, sa compatibilité Sylius 2.3 et son niveau de qualité (PHPStan, tests, couverture, scan de sécurité), afin de juger la fiabilité sur des faits.

## Contexte

**Recadrée le 2026-10-21 : c'est la preuve centrale du positionnement** (qualité, sécurité et conformité intactes). Les données viennent des dépôts (Packagist, CI) ; seuls des chiffres vérifiés sont affichés, avec le lien vers la source. La couverture n'est affichée que si elle est mesurée (US-084 n'est plus un prérequis : sinon « non mesurée »). Ajout d'une ligne « Comment cette démo est livrée » : nombre de tests, outils d'analyse, scan d'image et SBOM de la CI, tous publics.

## Critères d'acceptation

```gherkin
Fonctionnalité: Bloc de preuve technique : qualité, compatibilité, versions

  Scénario: Tableau complet (nominal)
    Étant donné les 24 plugins
    Quand la page est ouverte
    Alors chaque ligne affiche version, compatibilité et qualité vérifiées

  Scénario: Plugin non publié (alternatif)
    Étant donné un plugin non publié
    Quand la ligne est affichée
    Alors la version affiche « non publié »

  Scénario: Couverture non mesurée (alternatif)
    Étant donné un plugin sans mesure de couverture
    Quand la ligne est affichée
    Alors la couverture affiche « non mesurée » et non un chiffre estimé

  Scénario: Chiffre non vérifiable (erreur)
    Étant donné une donnée sans source
    Quand le contrôle s'exécute
    Alors elle n'est pas affichée

  Scénario: Source en échec (erreur)
    Étant donné Packagist ou la CI indisponible au moment du calcul
    Quand la page est affichée
    Alors la dernière valeur vérifiée est servie avec sa date, ou « non disponible », sans erreur 500
```

## Inventaire des sources et décision de forme (T-111-01, 2026-10-21)

| Fait affiché | Source publique vérifiée | Lien affiché |
|--------------|--------------------------|--------------|
| Version publiée | API publique de Packagist (`/packages/tmonier/<plugin>.json`) : plus haute version stable ; 404 ou aucune version stable = « non publié » | page Packagist du paquet |
| Compatibilité Sylius 2.3 | contrainte `sylius/sylius` de cette version, évaluée par `composer/semver` | page Packagist du paquet |
| Versions de Sylius testées | matrice du workflow de CI (fichier lu par l'API GitHub) | fichier du workflow sur GitHub |
| CI | dernière exécution terminée du workflow de CI sur la branche par défaut (les exécutions de Dependabot sont exclues) | page de l'exécution |
| PHPStan | niveau lu dans `phpstan.neon`, seulement si le workflow lance PHPStan | fichier de configuration sur GitHub |
| Tests | nombre de fichiers `*Test.php` et `*.feature` de `tests/` (arbre Git de la branche par défaut) | dossier `tests/` sur GitHub |
| Couverture | aucune CI ne publie de chiffre : **« non mesurée » partout**, jamais estimée | sans objet |
| Scan de sécurité des plugins | aucune CI de plugin ne lance `composer audit` : **non affiché** pour les plugins (un « non » répété 24 fois n'apprend rien) ; constat remonté à l'orchestrateur | sans objet |
| Démo (« Comment cette démo est livrée ») | workflow `ci.yaml` du dépôt de la démo : ECS, PHPStan, `composer audit`, Trivy (scan d'image), SBOM CycloneDX, nombre de fichiers de test, dernière exécution | fichier du workflow, dossier `tests/`, page de l'exécution |

**Forme retenue** : un fichier de données versionné (`config/demo/proof.json`) rafraîchi par une commande manuelle (`php bin/proof-refresh`, sources publiques seulement, `gh` pour GitHub, aucun secret ni `.env`), jamais par le reset, le build, la CI ni la page. La page (`/{locale}/preuve`) lit ce fichier : aucune requête réseau, donc aucune erreur 500 si une source est en échec ; elle sert la dernière valeur vérifiée avec sa date (`stale`) ou « non disponible ». Un fait sans source publique valide est abandonné au chargement. Détails : `docs/theme-b2b.md`.
