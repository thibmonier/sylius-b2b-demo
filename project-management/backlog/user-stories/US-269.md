# US-269 — Copilote commercial : Symfony AI 0.15, en préparant la 1.0

> Epic : [EPIC-10](../epics/EPIC-10.md) · Persona : Thibaut · MoSCoW : **Should** · Points : **3** · Sprint : sprint 48 · Statut : **ready-for-dev**
> Origine : veille des versions du 2026-11-04 (PR Dependabot #7 de `sylius-b2b-sales-copilot-plugin`, `symfony/ai-platform ^0.14 → ^0.15`). Décision de Thibaut : story au backlog.

## Story

En tant que Thibaut, je veux monter le copilote commercial sur Symfony AI 0.15 en gardant tout le code Symfony AI derrière un seul adaptateur, afin que le passage à Symfony AI 1.0 se résume à adapter ce fichier et ses tests.

## Contexte

Symfony AI est avant 1.0 : chaque montée mineure peut casser l'API (0.14 → 0.15 est traitée comme une majeure par la veille). Le plugin l'utilise uniquement dans `src/Infrastructure/SymfonyAi/SymfonyAiCopilotAdapter.php` (`PlatformInterface`, `MessageBag`, `SystemMessage`, `UserMessage`, `Text`). Il est déclaré en `require-dev` et en `suggest` : l'appel réel au LLM est optionnel (`ai.enabled: true`), le mode par défaut rejoue des cassettes.

La PR Dependabot #7 est verte, mais elle remplace la contrainte (`^0.15`) sans vérifier le comportement de l'adaptateur avec la nouvelle API. Les tests actuels passent par les cassettes et n'exercent pas l'adaptateur Symfony AI.

Pour préparer la 1.0 :
- aucune classe `Symfony\AI\*` hors de `src/Infrastructure/SymfonyAi/` (le domaine et l'application ne parlent qu'au port du copilote) ;
- un test de contrat du port, exécuté contre l'adaptateur avec une plateforme factice : il dira exactement ce qui casse à la 1.0 ;
- la contrainte suit une seule version mineure à la fois (`^0.15`), jamais un intervalle qui mélange des API incompatibles.

## Critères d'acceptation

```gherkin
Fonctionnalité: Copilote sur Symfony AI 0.15

  Scénario: Réponse du LLM (nominal)
    Étant donné le copilote avec ai.enabled à true et une plateforme Symfony AI 0.15 factice qui répond « 3 références trouvées »
    Quand un acheteur pose une question
    Alors la réponse affichée est « 3 références trouvées », avec le message système et la question transmis à la plateforme

  Scénario: Mode cassettes (alternatif)
    Étant donné ai.enabled à false
    Quand un acheteur pose une question connue
    Alors la réponse enregistrée est rejouée, sans appel à Symfony AI

  Scénario: Symfony AI absent (alternatif)
    Étant donné une installation sans symfony/ai-platform
    Quand le plugin démarre avec ai.enabled à false
    Alors il fonctionne, aucune classe Symfony AI n'est chargée

  Scénario: Erreur de la plateforme (erreur)
    Étant donné une plateforme qui lève une exception
    Quand un acheteur pose une question
    Alors la chaîne de repli (US-216) répond, et l'erreur est journalisée sans le contenu de la question

  Scénario: Fuite d'API (erreur évitée)
    Quand l'architecture est contrôlée (deptrac ou test PHPStan)
    Alors aucune classe Symfony\AI\* n'est utilisée hors de src/Infrastructure/SymfonyAi/
```
